# /feature — 기능 계획 준비

프로젝트의 AGENTS.md §2.1~2.3을 읽고 그 승인 정책을 사용한다. 이 스킬은 새 승인 조건을 만들지 않는다.

1. 요청·기존 docs·관련 specs를 확인한다. 메모리를 사용할 수 있으면 관련 맥락을 회수한다.
2. 기능 이름은 목적에서 kebab-case로 정할 수 있다. 목적·완료 기준이 불명확할 때만 질문한다. docs가 예시 상태면 확인 가능한 사실을 채우고, 목표 또는 중요한 설계 선택에 사용자 결정이 필요한 부분만 질문한다.
3. 진행 중인 동일 기능은 기존 문서를 갱신한다. 아카이브의 유사 기능은 배경으로 참조하고, 완료된 요구사항·기록을 덮어쓰지 않는다.
4. 새 기능이면 specs/_templates/의 spec, plan, tasks, context를 복사한다. 승인된 spec 변경은 사용자 지시가 필요하다.
5. spec에 목표·요구사항·비목표·검증 기준을, plan에 영향·작업 규모에 맞는 단계·검증 방법을 쓴다. ADR 필요 여부는 AGENTS.md §1.2로 판단한다.
6. tasks에 실행 순서와 근거를 기록한다. context에는 현재 상태·미해결 질문·승인 근거 또는 승인 대기 범위를 기록한다.
7. 계획과 검증 방법을 보고한다. 사용자가 실행을 요청했고 AGENTS.md §2.2의 승인 대상이 없으면 구현을 계속한다. 계획·검토만 요청했다면 문서 준비와 보고로 마친다. 승인이 필요한 부분은 구체적인 변경안을 준비해 질문하고 독립적인 준비는 계속한다.

실행·Phase 보고·완료 처리는 AGENTS.md가 원본이다.
